GitHub에 올리면 저절로 배포되게

Git → GitHub → Vercel 자동 배포

내 컴퓨터의 자기소개 페이지를 GitHub 저장소에 올리고 Vercel과 한 번 연결합니다. 그다음부터는 고친 내용을 GitHub에 올리기만 하면 같은 주소의 사이트가 새 내용으로 바뀝니다.

  • 도구 Git, GitHub, Vercel (Hobby), Codex 앱 또는 Claude Code

1단계

Git 설치와 GitHub 저장소 만들기

내 컴퓨터의 폴더를 인터넷에 올리려면 Git과 GitHub 저장소가 필요합니다. 처음 한 번만 합니다.

1. Git 설치

  1. 검색창에 “GIT 설치”를 검색해 Git - Install for Windows를 엽니다. 주소는 git-scm.com/install/windows입니다.
  2. Git for Windows/x64 Setup을 내려받아 실행합니다.
  3. 설치 화면의 선택지는 기본값 그대로 두고 끝까지 진행합니다.
  4. PowerShell을 새로 열어 아래 명령으로 확인합니다.
PowerShell에서 직접
git --version
확인할 것
  • git version 2.…처럼 버전이 나오나요? “인식되지 않습니다”가 나오면 PowerShell을 닫았다가 다시 엽니다.

2. GitHub 계정 만들기

  1. github.com에 접속합니다.
  2. Sign up을 누릅니다.
  3. 이메일 칸에 Gmail 주소를 넣습니다. (추천)
  4. 비밀번호와 사용자 이름(Username)을 정하고 가입을 진행합니다.
  5. Gmail로 온 인증 코드를 입력해 이메일 인증을 마칩니다.
Gmail로 가입하면 좋은 점
  • 회사 메일은 외부 인증 메일이 늦게 오거나 막히는 경우가 있습니다. Gmail은 인증 코드가 바로 옵니다.
  • 자리를 옮기거나 퇴직해도 계정을 계속 쓸 수 있습니다.
  • 같은 Gmail 주소를 아래 Git 작성자 정보에도 그대로 씁니다. GitHub 가입 이메일과 같아야 GitHub에서 내가 올린 기록으로 표시됩니다.

GitHub 사용자 이름은 저장소 주소에 쓰이므로 영문과 숫자로 된 간단한 이름을 권합니다.

3. 새 저장소 만들기

  1. GitHub에 로그인하고 오른쪽 위 + → New repository를 누릅니다.
  2. Repository name에 my-intro를 입력합니다.
  3. Public(누구나 코드 보기)과 Private(나만 보기) 중 하나를 고릅니다. 개인 계정 저장소는 둘 다 Vercel 무료 요금제로 배포됩니다.
  4. README 추가 같은 아래쪽 선택지는 체크하지 않고 Create repository를 누릅니다.
확인할 것
  • 브라우저 주소창이 https://github.com/내계정/my-intro처럼 바뀌었나요? 이 주소를 다음 단계에서 씁니다.
2단계

내 폴더를 GitHub에 올리기

my-intro 폴더를 방금 만든 저장소와 연결하고 올립니다. 올리기 전에 공개하면 안 되는 파일이 없는지 확인합니다.

1. Git 작성자 정보 등록

Git을 처음 쓸 때 한 번만 합니다. 아래 칸에 이름과 GitHub 가입 이메일(Gmail)을 넣으면 명령에 자동으로 들어갑니다. 복사해서 PowerShell에 붙여 넣고 실행합니다.

이름과 이메일을 넣으면 아래 명령에 자동으로 들어갑니다.
PowerShell에서 직접
git config --global user.name "(위 칸에 이름을 넣으세요)"
git config --global user.email "(위 칸에 이메일을 넣으세요)"
확인할 것
  • PowerShell에서 git config --global user.email을 실행하면 넣은 이메일이 나오나요?

2. 저장소 연결

  1. 저장소 화면에서 브라우저 주소창의 주소를 복사합니다.
  2. 복사한 주소를 아래 칸에 붙여 넣습니다. 명령에 주소가 자동으로 들어갑니다.
  3. 파일 탐색기에서 my-intro 폴더를 열고, 빈 곳에서 오른쪽 클릭 → 터미널에서 열기로 PowerShell을 엽니다.
  4. 아래 명령을 복사해 실행합니다.
주소를 붙여 넣으면 아래 명령에 자동으로 들어갑니다.
PowerShell에서 직접 · my-intro 폴더에서
git init
git branch -M main
git remote add origin (위 칸에 저장소 주소를 넣으세요)

저장소 화면 아래쪽 상자에 나오는 명령은 쓰지 않습니다. 파일을 올리는 일은 다음 프롬프트로 AI에게 맡깁니다.

3. AI에게 올리기 맡기기

my-intro 폴더를 AI 도구에서 엽니다.

  • Codex 앱 my-intro 폴더를 프로젝트로 추가하고 새 대화를 엽니다.
  • Claude Code Claude 데스크톱 앱의 Code 탭에서 my-intro 폴더를 고르고 새 세션을 엽니다.
AI에게
이 폴더를 GitHub의 origin/main에 처음으로 올리려고 해.
1. 공개되면 안 되는 파일(개인 연락처, 비밀번호, API 키, 개인 문서)이 있는지 먼저 확인해줘.
2. 시스템이 만드는 불필요한 파일은 .gitignore에 넣어줘.
3. 올릴 파일 목록을 보여준 뒤, “첫 업로드” 메시지로 커밋하고 origin/main에 푸시해줘.

처음 푸시할 때 브라우저에 GitHub 로그인 창이 뜨면 로그인하고 승인합니다. AI 도구가 명령 실행이나 인터넷 접속 권한을 물으면 승인합니다.

확인할 것
  • 올릴 파일 목록에 index.html이 있나요? Vercel은 이 파일을 첫 화면으로 엽니다.
  • GitHub 저장소 화면을 새로고침하면 파일이 보이나요?
주의
  • Public 저장소는 누구나 코드를 볼 수 있고, 배포된 사이트는 Private 저장소여도 주소를 아는 누구나 볼 수 있습니다. 집 주소, 개인 휴대폰 번호 같은 정보는 넣지 않습니다.
3단계

Vercel에 Hobby로 가입하기

Vercel 계정을 GitHub 계정으로 만듭니다. 그러면 Vercel이 내 GitHub 저장소를 바로 볼 수 있습니다.

  1. vercel.com/signup에 접속합니다.
  2. 요금제 종류에서 개인 프로젝트용 Hobby를 고릅니다. (“I’m working on personal projects”) 무료이고 카드 등록이 필요 없습니다.
  3. 이름을 입력하고 Continue를 누릅니다.
  4. 가입 방법에서 Continue with GitHub를 누릅니다.
  5. GitHub 창이 뜨면 로그인하고, Vercel 접근을 허용하는 Authorize Vercel을 누릅니다.
  6. Vercel 화면으로 돌아오면 가입이 끝납니다. 이후 Vercel에 들어갈 때도 Continue with GitHub로 로그인합니다.

Vercel 가입 ↗Vercel 대시보드 ↗

확인할 것
  • 오른쪽 위 프로필 사진이 내 GitHub 사진(또는 기본 그림)으로 보이나요?
  • 왼쪽 위 팀 이름 옆에 Hobby가 표시되나요?
주의
  • Hobby는 개인·비상업용입니다. 기관의 공식 서비스나 수익이 나는 사이트는 Pro 요금제가 필요합니다.
  • 이메일로 먼저 가입했다면, 설정의 Authentication에서 GitHub를 연결해 두면 다음 단계가 편합니다.
4단계

GitHub 저장소를 Vercel로 가져와 배포하기

Vercel에 my-intro 저장소를 가져오면(import) 첫 배포가 되고, 이때부터 GitHub에 올릴 때마다 자동으로 다시 배포됩니다.

1. 저장소 가져오기

  1. Vercel 대시보드 오른쪽 위 Add New… → Project를 누릅니다. 바로 가려면 vercel.com/new를 엽니다.
  2. Import Git Repository 목록에 내 저장소가 보입니다. 처음이면 Install(GitHub 앱 설치) 단추가 먼저 나올 수 있습니다. 누르고 GitHub 창에서 진행합니다.
  3. GitHub 창에서 저장소 범위를 묻습니다. Only select repositories를 고르고 my-intro를 선택한 뒤 Install(또는 Save)을 누릅니다. All repositories를 골라도 됩니다.
  4. 목록의 my-intro 오른쪽 Import를 누릅니다.
확인할 것
  • 목록에 my-intro가 안 보이면 목록 아래 Adjust GitHub App Permissions를 눌러 저장소를 추가합니다.
  • 목록 왼쪽 위 계정 이름이 내 GitHub 계정인가요?

2. 설정 확인하고 배포

Configure Project 화면이 나옵니다. HTML 한 파일짜리 사이트는 대부분 그대로 두면 됩니다.

항목이렇게
Project Namemy-intro 그대로 둡니다. 사이트 주소의 앞부분이 됩니다. 영문 소문자·숫자·하이픈만 됩니다.
Framework PresetOther로 둡니다. 다른 이름이 골라져 있으면 Other로 바꿉니다.
Root Directory./ 그대로 둡니다. index.html이 저장소 맨 위에 있으면 바꿀 필요가 없습니다.
Build and Output Settings건드리지 않습니다.
Environment Variables비워 둡니다. API 키를 쓰는 사이트일 때만 여기에 넣습니다.
  1. Deploy를 누릅니다. 빌드 기록이 흘러가고 잠시 뒤 축하 화면이 나옵니다.
  2. 미리보기 화면을 누르거나 Continue to Dashboard로 프로젝트 화면에 들어갑니다.
  3. Domains에 보이는 my-intro-….vercel.app 주소가 내 사이트 주소입니다. 이름이 비어 있으면 my-intro.vercel.app처럼 짧게, 이미 누가 쓰고 있으면 뒤에 글자가 붙습니다.
주소를 붙여 넣어 두면 아래 자동 배포 확인 프롬프트에 들어갑니다.
확인할 것
  • 사이트 주소를 휴대폰으로 열면 내 자기소개 페이지가 보이나요?
  • 프로젝트의 Settings → Git에 my-intro 저장소가 연결돼 있나요? 이것이 자동 배포의 연결 고리입니다.
5단계

고치고 올리면 저절로 바뀌는지 확인하기

이제 Vercel 화면에 들어가지 않습니다. 고치고 GitHub에 올리기만 하면 같은 주소가 새 내용으로 바뀝니다. main 브랜치에 올린 것은 실제 사이트(Production)로 배포됩니다.

1. 한 군데 고치고 올리기

눈에 잘 띄는 곳을 하나 고쳐야 바뀐 것을 확인하기 쉽습니다.

AI에게 · 색칠된 부분을 내 것으로
index.html의 첫 화면 한 줄 소개 문구를 “오늘 자동 배포를 배웠습니다”로 바꿔줘.
다른 곳은 고치지 마.
고친 뒤 변경 내용을 보여주고, “한 줄 소개 수정” 메시지로 커밋해서 origin/main에 푸시해줘.
푸시가 끝나면 커밋 번호(앞 7자리)와 커밋 메시지를 알려줘.

2. 자동 배포 확인

  1. Vercel 프로젝트의 Deployments를 엽니다. 방금 커밋 메시지가 적힌 새 배포가 맨 위에 생깁니다.
  2. 상태가 Building에서 Ready로 바뀔 때까지 기다립니다. 보통 1분 안팎입니다.
  3. 내 사이트 주소를 열고 Ctrl+F5로 새로고침해 고친 문구가 보이는지 봅니다.

AI에게 확인을 맡길 수도 있습니다. 위 내 사이트 주소 칸에 주소를 넣으면 아래 프롬프트에 들어갑니다.

AI에게 · 자동 배포 확인
방금 GitHub에 푸시한 변경이 Vercel에 자동 배포됐는지 확인해줘.
내 사이트 주소는 (위 ‘내 사이트 주소’ 칸에 주소를 넣으세요) 야.
1. git log로 origin/main의 최신 커밋 번호와 메시지를 알려줘.
2. 사이트 주소를 열어서 방금 고친 문구가 실제로 보이는지 확인해줘.
3. 아직 예전 내용이면 1~2분 기다렸다가 한 번 더 확인해줘.
4. 그래도 반영되지 않았으면 가능한 원인(푸시 실패, 다른 브랜치에 푸시, Vercel 연결 끊김, 배포 오류)을 순서대로 점검하고,
   내가 Vercel 화면에서 직접 볼 곳을 알려줘.
확인할 것
  • Deployments 맨 위 배포의 커밋 메시지가 방금 AI가 알려준 메시지와 같나요?
  • 상태가 Ready이고 환경이 Production인가요?
  • 사이트 주소가 바뀌지 않고 그대로인데 내용만 새것으로 바뀌었나요?

3. 앞으로는 이렇게

AI에게 · 고치고 바로 배포 · 색칠된 부분을 내 것으로
고칠 내용을 고쳐줘. 다른 곳은 그대로 둬.
고친 뒤 커밋해서 origin/main에 푸시해줘. Vercel이 자동으로 배포해.
잘못 올렸을 때 되돌리기

방금 배포가 마음에 들지 않으면 Vercel의 Deployments에서 이전 배포 오른쪽 ⋯ → Promote 또는 Instant Rollback으로 예전 화면을 바로 되살릴 수 있습니다. 코드도 되돌리려면 AI에게 아래처럼 보냅니다.

AI에게
방금 커밋을 되돌리는 커밋을 만들어서 origin/main에 푸시해줘. 이전 커밋은 지우지 마.
