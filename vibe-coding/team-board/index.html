Node.js 설치하기

이 프로젝트는 Node.js 서버로 실행되므로 Node.js 설치가 필요합니다. npm은 Node.js 설치 시 함께 설치됩니다.

  1. Node.js 공식 다운로드 페이지를 엽니다. 맨 위 버전 칸에 LTS 표시가 붙어 있는지 확인합니다. LTS는 안정적으로 오래 지원되는 권장 버전입니다.
  2. 가운데 명령 상자(fnm 설치 명령)는 쓰지 않습니다. 상자 바로 아래 “Or get a prebuilt Node.js® for Windows…” 줄의 Windows Installer (.msi) 단추를 눌러 내려받습니다.
  3. 내려받은 .msi 파일을 실행해 기본값 그대로 설치한 뒤 PowerShell을 새로 엽니다.
PowerShell에서 확인
node -v
npm -v

각각 버전 번호가 보이면 성공입니다. (2026년 11월 기준 v26.…)

fnm 명령으로 설치하지 않는 이유
  • 다운로드 페이지에 기본으로 보이는 fnm 방식은 명령을 입력한 그 PowerShell 창에서만 Node.js가 잡힙니다. 창을 새로 열면 node를 찾을 수 없다고 나올 수 있습니다.
  • 이 실습은 창 A·창 B와 AI 코딩 도구까지 여러 창을 쓰므로, 어느 창에서나 바로 되는 .msi 설치가 편합니다.
명령을 찾을 수 없다는 오류가 나면
  • PowerShell을 완전히 닫고 새로 열어 보세요. 그래도 안 되면 Node.js 설치를 다시 확인합니다.
헷갈리기 쉬운 점
  • 여기 나오는 프롬프트는 "정답"이 아니라 "실제로 보냈던 요청"입니다. 상황에 맞게 단어를 바꿔도 됩니다.
  • 프롬프트는 한 번에 하나씩 보냅니다. 여러 단계를 한 번에 섞어 보내면 AI가 범위를 넘어서기 쉽습니다.

바이브코딩이란

2 / 12

바이브코딩은 긴 요구사항을 한 번에 던지는 방식이 아닙니다. 작은 요청 → 결과 확인 → 다음 요청을 반복하며 AI와 함께 만들어 가는 방식입니다. 이번 실습은 10단계로 이 과정을 그대로 따라갑니다.

단계하는 일이 단계의 핵심 메커니즘
1. 작업 규칙AGENTS.md로 AI의 작업 방식을 먼저 합의규칙을 한 번 정하면 이후 모든 요청에 계속 적용됨
2. 기획서AI가 먼저 질문 → 내가 답 → PRD.md 저장코드를 짜기 전에 결정 사항부터 문서로 고정
3. 기술·순서기술 추천, 전체 순서 5단계 받기기술 선택을 AI에게 맡기고 큰 그림만 확인
4~7. 화면·기능화면 → 로그인 → 기능을 하나씩 구현"이것만", "다른 기능은 만들지 마"로 범위를 좁힘
8~9. 점검·공유데이터 확인·백업, 외부 공유완성 후에도 실행해서 직접 확인하는 습관
왜 이 순서인가 — 한 번에 다 만들어 달라고 하면 중간에 무엇이 잘못됐는지 찾기 어렵습니다. 단계를 작게 쪼개면, 문제가 생겨도 "방금 요청한 부분"만 다시 보면 되고, 매 단계가 끝날 때마다 실제로 눈으로 확인할 수 있습니다. 이 패턴은 현황판이 아닌 다른 어떤 프로그램을 만들 때도 똑같이 적용됩니다.

1. AI 작업 규칙 만들기

AI에게
이 폴더 구조에 대해 agent.md 파일을 만들어줘
왜 폴더부터 손으로 만드는가 — 빈 폴더라도 구조가 먼저 있으면 AI가 "이 프로젝트가 무엇을 담을 곳인지" 파악하고 그에 맞는 규칙을 씁니다. 구조 없이 바로 "규칙 파일 만들어줘"라고 하면, AI가 임의로 폴더를 새로 만들어 버릴 수 있습니다.
왜 먼저 이걸 요청하는가 — "한 번에 한 기능만", "바꾸기 전에 설명하기" 같은 규칙을 파일로 만들어 두면, 이후 모든 요청에서 AI가 같은 규칙을 지킵니다. 매번 "하나씩 해줘"를 반복해서 말하지 않아도 됩니다.
확인할 것

AGENTS.md는 Codex만의 규칙 파일인가요?
  • AGENTS.md는 Codex뿐 아니라 여러 AI 코딩 도구가 공통으로 읽는 표준 파일입니다.
  • Claude Code는 기본적으로 CLAUDE.md라는 이름을 쓰지만, AGENTS.md가 있으면 그것도 함께 인식합니다. 즉 AGENTS.md 하나만 만들어 둬도 Codex와 Claude Code 모두에서 같은 규칙으로 작동합니다.

DB Browser for SQLite로 데이터 들여다보기

DB Browser for SQLiteSQLite 파일을 엑셀처럼 표로 열어 보는 무료 프로그램

직접 다운로드 페이지를 찾아도 되지만, 설치 자체를 AI에게 맡길 수도 있습니다.

AI에게 (설치를 부탁하는 방법)
DB Browser for SQLite를 내 컴퓨터에 설치해줘.
winget이 있으면 winget으로 설치하고,
안 되면 공식 다운로드 링크와 설치 방법을 알려줘.
설치도 프롬프트로 요청할 수 있습니다 — AI 코딩 도구는 터미널 명령을 대신 실행할 수 있어서, "이 프로그램을 설치해줘"라고만 해도 되는 경우가 많습니다. 다만 설치 여부 확인이나 관리자 권한 요청 창이 뜨면 직접 눌러 줘야 합니다.
  1. AI가 설치를 못하거나 직접 하고 싶다면, DB Browser for SQLite 공식 다운로드 페이지에서 Windows용 설치 파일을 받아 설치합니다.
  2. 프로그램을 열고 Open Database로 Team Hub/src/data.db를 엽니다.
  3. Browse Data 탭에서 테이블(users, duty, leave, schedule 등)을 선택하면 표 형태로 데이터가 보입니다.
헷갈리기 쉬운 점
  • npm start로 서버가 실행 중일 때 DB Browser에서 값을 직접 수정하고 저장하면, 서버가 쓰던 내용과 충돌할 수 있습니다. 값은 되도록 화면(브라우저)에서 등록·수정하고, DB Browser는 "확인용"으로만 씁니다.
  • 부득이 직접 수정해야 한다면 서버를 Ctrl + C로 멈춘 뒤 수정하고, 끝나면 다시 npm start로 켭니다.

백업하기

PowerShell에서 직접
Copy-Item .\data.db ..\archive\data-backup-날짜.db
왜 화면으로 만든 걸 파일로도 확인하는가 — 화면에 잘 보인다고 데이터가 안전하게 저장된 것은 아닙니다. DB Browser로 파일을 직접 열어 보면 "진짜 저장이 됐는지"를 화면과 별개로 확인할 수 있고, 문제가 생겼을 때 데이터 자체를 보고 원인을 찾을 수 있습니다.

Cloudflare Tunnel로 외부 공유

11 / 12

내 PC에서 실행 중인 앱을, 코드를 다른 서버로 옮기지 않고 URL로 바로 연결합니다.

전제 조건
  • PC, npm start, cloudflared가 모두 켜져 있어야 합니다. 하나라도 꺼지면 URL도 열리지 않습니다.

1. cloudflared 다운로드

Cloudflare 공식 다운로드 안내에서 Windows 64비트 파일(cloudflared-windows-amd64.exe)을 받습니다.

2. 창 A에서 앱 실행

창 A · PowerShell
cd ...\src
npm start

3. 창 B에서 Tunnel 실행

창 B · PowerShell
.\cloudflared-windows-amd64.exe tunnel --url http://localhost:3000

https://...trycloudflare.com 형태의 주소가 나오면 다른 PC나 휴대폰에서 열어 봅니다.

실행할 때마다 주소가 바뀌나요?
  • 네. Quick Tunnel(--url로 바로 실행하는 방식)은 실행할 때마다 임의의 새 주소가 발급됩니다. 어제 공유했던 주소를 오늘 그대로 쓸 수 없습니다.
  • cloudflared 창을 끄면 그 주소는 즉시 작동을 멈춥니다. 다시 켜면 또 다른 새 주소가 나옵니다.
  • 항상 같은 주소를 쓰고 싶다면 아래 "실제로 배포하려면"의 Named Tunnel을 사용해야 합니다.

실제로 배포하려면

지금 방식(Quick Tunnel)은 테스트용입니다. 팀이 계속 쓸 고정 주소가 필요하면 아래 순서로 넘어갑니다.

  1. Cloudflare 계정을 만들고, 이미 가지고 있는 도메인을 Cloudflare에 연결합니다. (도메인이 없다면 먼저 구입해야 합니다.)
  2. cloudflared tunnel login으로 로그인하고, cloudflared tunnel create 이름으로 Named Tunnel을 만듭니다.
  3. 설정 파일에 로컬 주소(http://localhost:3000)와 연결할 도메인 주소를 적습니다.
  4. cloudflared tunnel route dns 터널이름 사용할주소로 도메인과 터널을 연결합니다.
  5. cloudflared tunnel run 터널이름으로 실행하면, 이후부터는 항상 같은 주소로 접속됩니다.
그래도 PC는 계속 켜져 있어야 합니다
  • Named Tunnel을 써도 "내 PC의 서버를 연결"하는 방식은 같습니다. PC, npm start, cloudflared 중 하나라도 꺼지면 접속이 끊깁니다.
  • PC를 계속 켜 두기 어렵다면, Render·Railway 같은 클라우드 호스팅에 이 Node.js 앱을 올려 24시간 운영하는 방법도 있습니다. 이 경우 AI에게 "이 프로젝트를 [서비스 이름]에 배포하고 싶어, 방법을 알려줘"라고 물어보면 됩니다.
확인할 것
  • https://...trycloudflare.com 주소를 휴대폰 데이터 환경에서 열어 봤나요?
  • 창 B(cloudflared)를 껐다 켜면 주소가 바뀐다는 것을 직접 확인해 봤나요?
